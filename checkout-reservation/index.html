AYLO Core · Commerce architecture

A checkout URL is not proof of ownership.

When a digital item has a visible supply of one, opening a payment page cannot be treated as a completed purchase. Two visitors may try to buy the same identity at nearly the same time.

Reserve on the server

The AYLO Core checkout architecture creates a temporary server-side reservation before redirecting to the hosted payment page. The reservation and checkout session share an expiration boundary. If session creation fails, the reservation is released. Completion is handled separately from session creation.

Three durable rules

  1. Never let the browser decide that inventory is reserved.
  2. Make reservation and release operations idempotent.
  3. Treat a generated checkout URL as pending state, not proof of payment.

The hosted checkout handoff is the verified boundary discussed here. This note does not claim a completed production payment.
